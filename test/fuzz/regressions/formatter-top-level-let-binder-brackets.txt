At the top of a file the head of a `let` is read as the name being
defined, so the brackets around a pattern there are the syntax and not
decoration. The formatter dropped them, and the three shapes in this file
each break a different way.

  let (e.I) = ""         parse stops at the dot
  let (E) = []           reads as a value named E, not a match against
                         the constructor -- so a file that did not
                         typecheck came back as one that does
  let (Some x) = Some 1  reads as a one-clause definition of a function
                         named Some

A `let ... in` and a block binding parse their head as a pattern already
and need no brackets, so the rule is the top level's alone.

Since #208 the top level reads an upper-case head with more after it as a
pattern, so `let Some x = Some 1` needs no brackets and `wand f` drops
them. The other two shapes still need them, and keep them.
